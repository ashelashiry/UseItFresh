02 The status system

The most important component in the app, and the one most likely to be got wrong. These nine are fixed by spec §10 — not a palette decision. Every one carries an icon and a word, because §10 forbids relying on colour alone, and because a colour-blind user still needs to know whether to eat something.

Past use-by and past best before must never look alike

One is "throw this out", the other is "have a look at it". Spec §5.2 turns on that difference and the database already encodes it. Red belongs only to the first; the second is a muted brown so it reads as a prompt, not an alarm.

Every row also carries a status_basis — "past the printed use-by", "open too long", "a typical shelf life — no date recorded" — plus a has_unknowns flag. The UI should show its reasoning and admit its gaps (§5.4, §5.9), not project confidence it doesn't have.
