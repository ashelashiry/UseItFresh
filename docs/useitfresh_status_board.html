04 Worth knowing

One thing that cost real time

Batching removals with position-sensitive inserts in the DSL is unsafe. Removals shift sibling indices as they apply, so later operations in the same batch hit the wrong nodes. Three passes removed the wrong things; one destroyed the whole use-first section and another overwrote the hero card's contents — each time with a clean, successful push and no error. I rebuilt Home's children in a single deterministic pass instead, and structural work is now one operation per push.

Other traps, recorded

  • maxLines sets max characters. The patch named maxLines(2) writes FlutterFlow's overridden max characters, so the greeting rendered as "Go" and the empty state as "Not".
  • Container styling silently no-ops. color, borderRadius and visible apply to Buttons but do nothing on a Container, which made two passes look successful when nothing had changed.
  • Full width is Infinity, not a percentage. Setting a height also clears the width, which is why both quick-add buttons collapsed to hug their labels.
  • No conditional-value expression exists. A container cannot pick its own colours from a condition, so selected states need a rest/selected variant pair — or a custom widget, which is what the status badge became.
  • Newly inserted widgets are not selectable until the next push, and preflight requires every component parameter to be referenced in the tree, so bindings often have to be written inline rather than in a second pass.

How to report problems

Screen recordings work well. Drop them in design/Screen Recordings and I will find the problems myself — I read the DevTools console in the frames too, which is where most of the signal was last time.
