01 The build is fixed

The save action's Dart body had grown a sixth parameter for the photo, but its declared argument list still had five. FlutterFlow writes call sites from the declaration, so it emitted a five-argument call against a six-argument function and the web build stopped.

What actually made it stubborn. Declaring the argument on its own does not validate — FlutterFlow refuses a declared custom action argument that any call site fails to supply. So the declaration and the wiring on the review screen's confirm button had to land in a single push. My earlier attempt read the six identical complaints as six orphaned values and rewrote all the argument keys, which was the wrong diagnosis of the right symptom. The five live keys are now preserved untouched and the sixth was cloned from an existing one so its data type matches by construction.

Verified rather than assumed: flutter build web --release is green, and the app was driven in a browser through the entrance, sign-in and into the kitchen with the console watched throughout. The only errors left are the two local-export 404s (manifest.json, app-icon-512.png), which are artefacts of serving an exported build rather than defects in the app. localhost:8080 is serving the new build.
