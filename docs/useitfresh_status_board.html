01 Built today

Each one driven in a browser end to end and checked against the database afterwards, not just looked at.

FeatureWhat it does, and what it proved
Photo captureBuilt weeks ago, never once run. Camera → the household's own folder → signed URL → review → the item. The card and the details hero both show your photograph instead of the illustrative one.
Barcode lookupOpen Food Facts: open, no key, no quota. Type the number, get the real product — name, brand, size, photograph — and the add form starts already filled in. Saved with its barcode and marked as coming from one, so the same product can be recognised again later.

The scanner is native-only and needs a device; the lookup is the valuable half and works today.
Shopping listTable existed since day one, no screen. Add, tick, remove, shared with the household. Bought things stay on the list struck through rather than vanishing — in the aisle the useful question is "has someone already got this?", and an item that disappears cannot answer it.
What you usedThe payoff for logging every outcome since day one. Used up against thrown out over thirty days, which category goes in the bin most, and whether it is better than the month before. No chart — with a household's worth of data a chart would be four bars pretending to be a trend. It says nothing rather than inventing a pattern: no worst category until three things have gone and one clearly leads, and no month-on-month comparison until there is a month to compare against.
Replace what you finishThis is the loop the app is for. A toggle on the item screen: Put it on the shopping list. It applies whether you used it up or threw it out — running out of milk is a more common reason to need more than wasting it is. Off by default; nothing is ever added because the app guessed.

02 What driving it caught

Sixteen faults today. Every one of them passed validation and pushed cleanly first — none would have been found by reading the code.

FaultWhy it mattered
A chocolate bar filed as bakeryThe category exists only to estimate shelf life, so this would have had the app claim a Mars bar was going off within the week. It now reads 180 days. Caught because the mapping was tested against forty real products.
A stretching row hid three cards below itA Row set to stretch inside a scrollable Column has no height to stretch to. It fails layout and takes every sibling after it down with it — the same family as the shrink-wrap bug that broke two screens before. The values were computed and stored correctly and simply never drawn.
"I used it" only worked when something else had failedActions written after a conditional are nested into it. The settle ended up inside a failure branch, so finishing an item did nothing on the ordinary path.
Adding to the shopping list was silently refusedRow security requires the client to supply created_by. Without it every insert was rejected while the screen looked like it had worked.
Two new fields swallowed the first keystroke batchEvery new text field arrives with a two-second debounce, so tapping straight after typing used the previous value. It answered "that does not look like a barcode" about a perfectly good barcode.
The review screen omitted the photographIt said "this is what will be recorded" and left out the one thing you cannot check anywhere else.
Database codes on screen againvegetables rather than "Vegetables", and the raw storage type under every location name.
Every storage location wore a fridge iconThose rows were still the stock list FlutterFlow generates. The right icons already existed and were being used correctly elsewhere.
Choosing a location did not look like choosingThe row looked identical to the two it was not, so the list read as three buttons that did nothing.
The loading indicator had a diameter of zeroOn a phone that is the difference between "it is working" and "nothing happened".
Six tap targets under the recommended sizeFlagged on every push for weeks. All now 48px.
Every one of these is written up in HANDOVER.md section 5, which is now twenty-eight traps in this DSL that each produced a successful push and a wrong app.
