01 The one thing that needs you

Not urgent and not blocking — email sign-in works, and everything in section 2 proceeds without it. But it has a long tail (Apple review, real devices), so the earlier it starts the better.

Google and Apple sign-in credentials ~50 min, once

These go together: if you offer Google on iPhone, Apple's review rules require Apple sign-in too. The full step-by-step is unchanged from the last board — Google Cloud Console → Web client, then Supabase → Providers; Apple Developer → Services ID + Key, then Supabase. You have done both before on Spot a Paw, on this same Supabase setup.

Do the Web client only. Android needs a keystore SHA-1 that does not exist yet and iOS needs the app registered with Apple — both belong at release.
Secrets rule, unchanged. Client IDs, Services ID, Team ID and Key ID are safe to send me. The Google client secret, the Apple .p8 file, the service-role key and the database password go into Supabase and nowhere else — never into the app, a message, or the repo.

Three DSL traps, recorded so they do not recur

Each of these produced wrong output silently — no error, a successful push, and a broken screen. They cost most of the time in the last stage.

  • maxLines sets max characters. The patch named maxLines(2) writes FlutterFlow's overridden max characters, so the greeting rendered as "Go" and the empty state as "Not". Real line limits live in a different field.
  • Container styling silently no-ops. color, borderRadius and visible apply to Buttons but do nothing on a Container, which made two earlier passes look successful when nothing had changed. Containers have to be set on the node.
  • Full width is Infinity, not a percentage. This project expresses a full-width button as pixels = Infinity; a percent-of-parent width is ignored by codegen. Setting a height also clears the width, which is why both quick-add buttons collapsed to hug their labels.
