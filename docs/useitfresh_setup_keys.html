Never send me

  • Google client secret

  • Supabase service-role key or database password

App Store Connect API key

~15 min · free

Lets FlutterFlow upload builds to TestFlight without a Mac.

  1. Open appstoreconnect.apple.com → Users and Access → Integrations → App Store Connect API.
  2. Generate a Team key with the App Manager role. Admin also works. App Manager is the least privilege that can upload builds.
  3. Download the .p8 immediately. Apple shows it exactly once and there is no second chance — you would have to revoke and start again.
  4. From that same page, note the Key ID and the Issuer ID. Those two are safe to send me if it helps.
  5. Register the bundle ID com.useitfresh.app at developer.apple.com → Identifiers, then create the matching app record in App Store Connect. The bundle ID is already set in the project, so it must match exactly.
  6. In FlutterFlow: Settings & Integrations → App Settings → Mobile Deployment. Paste the Key ID and Issuer ID, and upload the .p8 there.
Lands in FlutterFlow only. The .p8 never touches the repo — .gitignore already blocks *.p8 — and never comes to me.

Track C — the sign-in buttons that do nothing

Google and Apple sit on the sign-in card as stand-ins today — they are drawn, not wired. Optional, but Apple requires Sign in with Apple on any app that offers another social login, so these two ship together or not at all.

Google sign-in

~20 min · free
  1. Google Cloud Console → APIs & Services → Credentials.
  2. Configure the OAuth consent screen first, or credential creation is blocked.
  3. Create OAuth client IDs: one iOS (bundle com.useitfresh.app) and one Web. The Web one is what Supabase uses.
  4. In Supabase: Authentication → Providers → Google. Paste the Web client ID and client secret, and enable it.
  5. Copy the callback URL Supabase shows there back into the Google credential's authorised redirect URIs.
  6. Send me the client IDs only. I will wire the buttons.
Lands in Supabase only. The client secret stays there.

Sign in with Apple

~25 min · needs the developer account
  1. Apple Developer → Identifiers. On the com.useitfresh.app App ID, enable the Sign in with Apple capability.
  2. Create a Services ID (a separate identifier, e.g. com.useitfresh.signin) and enable Sign in with Apple on it. This is the one that carries the web redirect.
  3. Under Keys, create a key with Sign in with Apple enabled. It downloads a .p8 — again, once only.
  4. Collect your Team ID (top right of the developer portal) and the new Key ID.
  5. In Supabase: Authentication → Providers → Apple. Enter the Services ID, Team ID, Key ID, and paste the .p8 contents into the secret field.
  6. Put the callback URL Supabase gives you into the Services ID's Return URLs.
  7. Send me the Services ID, Team ID and Key ID. Never the .p8.
Lands in Supabase only.
