First: Apple says "App ID" for two different things

This is what my earlier instructions got wrong, and it is the single most confusing thing in the whole process. They are not the same, you need both, and they are created in different places at different times.

App ID (= Bundle ID)
com.useitfresh.app
A reverse-domain name you choose. Registered at developer.apple.com. Already set inside the project, so it must match exactly. Part 1 creates this.
Apple ID (of the app)
6478123456
A ten-digit number Apple assigns when you create the app record. You cannot choose or guess it. Part 2 creates it, Part 3 finds it.
So The field FlutterFlow labels "App ID" wants the ten-digit number on the right — not com.useitfresh.app. And you cannot get that number until the app record exists, which you cannot create until the bundle ID is registered. Hence the order below.

Part 1 of 6 · done

Register the Bundle ID

developer.apple.com · ~5 min
  1. Go to developer.apple.com/account → Identifiers and sign in. The full path if that link moves: Account → Certificates, Identifiers & Profiles → Identifiers (left sidebar).
  2. Check the list first. If com.useitfresh.app is already there, skip to Part 2.
  3. Click the blue + next to the "Identifiers" heading.
  4. Select App IDs → Continue.
  5. Select type App (not App Clip) → Continue.
  6. Description: type Use It Fresh Internal label only. Apple rejects punctuation and emoji here — letters, numbers and spaces.
  7. Bundle ID: choose Explicit (not Wildcard), and enter exactly: com.useitfresh.app Must match character for character — it is already baked into the project.
  8. Capabilities: leave everything unticked for now. Push Notifications and Sign in with Apple get enabled here later, when we actually build those. Ticking them early does no harm but is not needed.
  9. Continue → review the summary → Register.
Done when com.useitfresh.app appears in the Identifiers list.
Part 2 of 6 · done

Create the app record

appstoreconnect.apple.com · ~5 min
  1. Go to appstoreconnect.apple.com → Apps.
  2. Click the blue + above the app list → New App.
  3. Platforms: tick iOS only.
  4. Name: Use It Fresh This is the public App Store name and must be unique across the entire store. If it is taken, Apple says so immediately — try "Use It Fresh: Food Waste" or similar. It can be changed later, before you publish.
  5. Primary Language: English (U.K.) or English (U.S.), your choice.
  6. Bundle ID: open the dropdown and select com.useitfresh.app. This is the step that needs Part 1. If the dropdown is empty or the ID is missing, Part 1 did not complete — go back and finish it, then reload this page.
  7. SKU: useitfresh-ios-001 Your own internal reference. Never shown to anyone. Any unique string will do.
  8. User Access: Full Access.
  9. Click Create.
If it refuses App Store Connect blocks new apps while an agreement is outstanding. Go to Business (or Agreements, Tax and Banking) and accept anything pending. For a free app you only need the free-apps agreement; you do not need to enter bank details.

Part 4 of 6 · done

Generate the API key

appstoreconnect.apple.com · ~5 min
  1. Top of App Store Connect, click Users and Access.
  2. Click the Integrations tab.
  3. In the left sidebar choose App Store Connect API, and make sure you are on Team Keys (not Individual Keys). First time only: a "Request Access" button appears. Click it and accept — it is instant.
  4. Copy the Issuer ID now. It sits above the key table, labelled Issuer ID. A long UUID like a1b2c3d4-.... One per team. Easy to miss because it is not part of the key row itself.
  5. Click + to generate a key.
  6. Name: FlutterFlow deploy
  7. Access: select App Manager. The least privilege that can upload builds. Admin also works but grants more than needed.
  8. Click Generate.
  9. On the new row, click Download and save the .p8 file somewhere you will not lose it.
  10. From that same row, copy the Key ID (ten characters, like 7ABC123DEF).
One chance Apple lets you download the .p8 once. Miss it and there is no recovery — you revoke the key and generate a new one. Download it before you leave the page.

Fill FlutterFlow in

FlutterFlow · ~5 min
  1. Open the project, then Settings & Integrations (the gear, bottom left) → App Settings → Mobile Deployment.
  2. Under Version: leave App Version as 1.0.0 and set Build Number to 1. Yours is currently EMPTY — I could see that on your screenshot. An upload without a build number is rejected. Raise it by one for every future upload; App Store Connect refuses a repeated build number even within the same version.
  3. In the App Store section, fill the four fields:
  4. Issuer ID → paste from Part 4, step 4.
  5. Key ID → paste from Part 4, step 10.
  6. Private Key → click Upload Private Key and choose the .p8 from Part 4, step 9.
  7. App ID → 6810644731 Your real value, from Part 3. NOT com.useitfresh.app — see the callout at the top of this page.
  8. Open Deployment Source and confirm it is pointing at the branch you want shipped — main.
  9. Open Privacy Manifest Configurations and work through it. Apple requires declared reasons for certain APIs. This app uses the camera, the photo library and local storage. A missing manifest is a rejection AFTER a 20-minute upload, so it is worth the two minutes now.
Already done The camera, photo-library and notification permission descriptions are configured in the project — I checked. You do not need to write those.
Part 6 of 6

Deploy, and install on the phone

FlutterFlow → TestFlight · ~30 min mostly waiting
  1. On that same Mobile Deployment page, click Deploy to App Store.
  2. Wait. FlutterFlow builds in the cloud — usually 15 to 30 minutes. You can close the tab; it keeps going. If it fails, the error names the step. Send me the message and I will read it.
  3. When it finishes, go to App Store Connect → your app → the TestFlight tab.
  4. The build appears with status Processing for another 5–15 minutes. Wait for that to clear.
  5. Answer the Export Compliance question when prompted. This app uses only standard HTTPS, which is the exempt case. Answer honestly based on what Apple asks on screen — if unsure, send me the exact question.
  6. In the left sidebar under TestFlight, open Internal Testing, create a group, and add yourself using your Apple Account email. Internal testers need no App Review. External testers do — stay internal for now.
  7. On your iPhone, install TestFlight from the App Store, sign in with the same Apple Account, and Use It Fresh will be waiting.
This unlocks Barcode scanning with the real camera, push notifications, the native camera, and proper large-text accessibility testing — the four things I cannot verify in a browser.

Track C — the sign-in buttons that do nothing

Google and Apple sit on the sign-in card as stand-ins today — drawn, not wired. Optional. Note that Apple requires Sign in with Apple on any app offering another social login, so these two ship together or not at all.

Optional

Google sign-in

console.cloud.google.com + Supabase · ~20 min
  1. Open Google Cloud Console → APIs & Services → Credentials.
  2. Configure the OAuth consent screen first — credential creation is blocked until you do. External user type; fill app name, support email, developer email.
  3. Create Credentials → OAuth client ID → type Web application. Name it Use It Fresh web. Create it, then copy the Client ID and Client secret.
  4. In Supabase: Authentication → Providers → Google. Enable it, paste the Client ID and Client secret, and save.
  5. Supabase shows a Callback URL on that same panel. Copy it.
  6. Back in Google Cloud, edit the Web client and paste that URL into Authorised redirect URIs. Save.
  7. Create a second OAuth client, type iOS, bundle ID com.useitfresh.app. Copy its Client ID.
  8. Send me both Client IDs. I will wire the buttons.
Lands in Supabase only. The client secret stays there and never comes to me.
Optional

Sign in with Apple

developer.apple.com + Supabase · ~25 min
  1. developer.apple.com → Identifiers → click com.useitfresh.app → tick Sign in with Apple → Save.
  2. Back in Identifiers, click +, choose Services IDs → Continue.
  3. Description Use It Fresh Sign In, Identifier com.useitfresh.signin → Continue → Register. A Services ID is a separate identifier from the app's bundle ID. It carries the web redirect.
  4. Open the new Services ID, tick Sign in with Apple, click Configure, and set the primary App ID to com.useitfresh.app. Leave the URLs blank for the moment — you fill them in step 8.
  5. In the sidebar go to Keys → +. Name it Use It Fresh Apple Sign In, tick Sign in with Apple, Configure → pick the primary App ID → Save → Continue → Register.
  6. Download the .p8 — again, one chance only. Note the Key ID on that page.
  7. Find your Team ID: top right of the developer portal, under your account name. Ten characters.
  8. In Supabase: Authentication → Providers → Apple. Enable it and enter the Services ID, Team ID, Key ID, and paste the .p8 contents into the secret field. Save, then copy the Callback URL it shows and paste it into the Services ID's Return URLs back at Apple.
  9. Send me the Services ID, Team ID and Key ID. Never the .p8.
